# 归屿 20261102(01) Windows

提供 32 位、64 位安装包和 ZIP 解压包。安装包双击 `-setup.exe` 按向导安装；解压包须解压整个文件夹，再双击 `Guiyu.exe`。不需要安装 Node.js，不要只拷贝 exe。

- Windows 10 32位：下载 Windows-ia32 包。
- Windows 10 / Windows 11 64位：下载 Windows-x64 包。
- Windows 11 没有32位系统；未针对 Windows ARM64 验证。
- 主窗口延续森林绿导航、薄荷绿项目栏、白色文件栏及小鸡图标；使用 Windows 系统标题栏和字体。

首次打开通过“＋”关联项目总目录；左栏显示其直接子目录，中间显示项目，右栏显示当前项目的直接子项。首次安装分类为空，点击“请设置文件分类”添加分类。可点“体验示例空间”使用隔离的临时示例。

支持三种视图、名称多关键词搜索、项目月份/修改时间排序、子文件夹导航、Ctrl/Shift多选、分类拖放、手动/智能命名、批量命名、智能归档和撤销、分类规则及豆包剪贴板流程。命名和归档均需明确确认，重名不覆盖；文件仍保留于本机原有目录。刷新只读取文件元数据。

路径导航以右侧当前项目（或中栏选中的来源文件夹）为根，进入子文件夹后显示“项目文件夹 / 子文件夹 / 当前文件夹”；不显示盘符、项目总目录或年份目录。各上级层均可点击跳转，当前层单独标识；绿色下划线、悬停底色与键盘焦点提示可点击，并提供路径层级菜单；左侧“上一级”仅返回到当前项目根目录。超长路径可横向滚动查看，完整路径可悬停查看。

智能命名提供“仅识别的名称 / 月份 + 识别的名称 / 月日 + 识别的名称 / 分类 + 识别的名称”四种格式，文件夹与文档独立设置。缺少设置字段时默认仅名称，已有明确选择保留。标题只清理排版空白和文件名非法字符，保留“方案”等词、书名号和数字，不拼接单位名，不剥离标题中的日期或分类文字。分类与仅名称模式允许手工修改分类和日期；扩展名保留原有大小写。

标题识别严格限定在首页或前两页：PDF按物理页，带已保存分页标记的DOCX到第2页截止，找不到标题也不继续翻页。Word没有可靠分页时仅用开头300字，候选标注“Word 开头节选”；旧DOC/RTF需要桌面Word本地转换，同样只取开头300字。Excel仅识别可见工作表前8行、16列的表头；前3列最多延伸至第30行，仅拼接相邻单字纵向表头，不使用后部正文或隐藏表，不执行公式。旧XLS保留原名。单文档不借用其他文件标题；文件夹从内部少量代表文档取候选。

无明确标题时保留精确原名，不因命名格式添加前缀；单个条目不改输入直接确认会关闭弹框，不改文件、不产生改名记录。批量无标题项默认不勾选，可以手工编辑再勾选。只有明确确认才会改名，同名不覆盖。关闭命名弹框会取消后续标题读取；已发起的旧Word本地转换或单图OCR可能需要等当前有界任务结束。

主窗口自动记住普通窗口的大小和位置，下次启动恢复；无记录时为1280×820，最小1060×700。保存文件与工作区配置分开，位于 `%APPDATA%\Guiyu-Windows\window-frame-v1.json`。全屏、最小化和最大化画面不覆盖普通窗口记录；显示器变化时重新适配可见工作区域。

下载和桌面采用中栏的普通文件列表，沿用同一刷新/排序工具栏，右侧保持空白。关联来源文件夹双击后在中栏进入，路径从该来源根目录开始；不显示额外标题或重复工具栏。项目内路径保持“项目根目录”起点，绿色下划线文字无背景与描边，仍可直接跳转和通过菜单选择层级。

快捷键：Ctrl+C 复制选中的文档或文件夹，可到资源管理器按 Ctrl+V 粘贴（支持多选）；输入框仍复制文字。空格预览；Enter打开；F2更名；Ctrl+A全选；Delete移入回收站（有确认）；Ctrl+F搜索；Ctrl+R刷新。

安装程序自动创建桌面“归屿”启动图标，并为文件和文件夹注册“归屿-智能命名”“归屿-智能归档”右键入口，卸载时移除。解压包可在设置→文件位置安装/移除入口；移动解压目录后需重新安装入口。Windows 11 中可能位于“显示更多选项”。

可归档目录默认提供“下载”和系统“桌面”，包括系统重定向后的桌面路径。升级时把旧“最近使用”入口替换为“桌面”，保留其他自定义关联。恢复默认入口会恢复下载和桌面；移除关联不删除文件。

## 系统适配与当前限制

Windows 版提供以下功能与系统适配范围。本次已在当前 Windows 电脑启动并进行部分界面检查；Win10 x86/x64、Win11 x64 的完整兼容性、OCR、Office、回收站、跨磁盘归档和右键入口仍需分别实测。

- PDF优先读取文字层；扫描PDF/图片按需调用 Windows 本地OCR，需要系统安装相应中文/英文OCR语言组件。OCR失败会提示，可手工输入名称。
- DOCX/XLSX/UTF-8与UTF-16文本本地提取；旧DOC/RTF提取需要安装桌面版Microsoft Word。旧XLS不提取正文。
- PDF/图片使用独立预览窗；Office显示提取文本，双击仍用本机默认软件编辑。尚无与macOS Quick Look完全相同的Office排版预览。图片格式受系统解码器限制。
- Windows 可归档目录使用下载、桌面及用户关联文件夹，直接读取当前层，不提供“最近使用”入口。
- 目前名称检索使用本地内存元数据，未迁移macOS的SQLite索引；大型目录的搜索响应仍需压力测试。
- 归档推荐和标题识别均使用本地规则；图片和扫描 PDF 使用内置的中文、英文 OCR，复杂排版和特殊 Excel 结构仍需核对。Windows文件夹命名最多采样4层、1000项元数据，再按5/3/2/2上限挑选代表文档，与Mac全库元数据加载方式存在差异。
- 检查更新按 Windows 自身的版本号查询 GitHub 发行记录（兼容早期发布记录），识别当前程序位数对应的 EXE 安装包或 ZIP 解压包。只有版本更高才显示“下载更新”，同版本或更低版本不会重复提示；点击后直接打开匹配的官方包。下载后关闭归屿，再运行安装程序或解压新版。Mac 的新版本号不代表 Windows 也有更新；尚未实现与 Sparkle 等价的签名自动安装流程。
- 尚未做Windows代码签名；源码提交不等于发布安装包。
- 32位框架固定Electron 43.8.6；后续框架版本不再提供x86，需持续维护兼容分支。
- 配置：`%APPDATA%\Guiyu-Windows\settings.json`，正文不持久化。配置与Mac版独立，不能直接复制含Mac路径的配置。
- 跨磁盘目录归档采用复制、校验、删除；失败时保留源或停止剩余项，可能留下目标副本，请按错误提示核对。批量文件操作不具有事务性。

## 开发

安装 Node.js 22.13+ 或 24+，在本目录运行：

```
npm ci --omit=optional
npm test
npm start
npm run package
```

Windows 打包输出 32 位和 64 位 ZIP 以及对应的 `-setup.exe` 安装程序。生成安装程序需要 NSIS 3；设置环境变量 `GUIYU_MAKENSIS` 指向 `makensis.exe`，或使用 electron-builder 缓存中的 NSIS 3.0.4.1。生产依赖不含平台原生模块，PDF文字提取不依赖native canvas。`npm run preview` 仅启动内存示例界面，不访问用户项目。

OCR 使用随包携带的 Tesseract.js 7.0.0 与简体中文、英文模型，不需要联网或另行安装 OCR。文本 PDF 优先提取原有文字，扫描页会进行识别；扫描 PDF 最多读取前两页，超过 30 MB 的扫描 PDF 需手动命名。识别结果不一定准确，使用前请核对。

许可证：MIT；Electron、PDF.js、Tesseract.js、fflate、DOMMatrix及其他依赖保留各自许可证。交付包内附框架 LICENSE 和依赖许可证。

Windows 版本独立由 `Windows/version.json` 决定；`node scripts/version.cjs` 会同步 package 元数据，打包时也会同步。Mac 版本继续使用自身的版本配置。
