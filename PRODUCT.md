# Product

## Platform
macOS native desktop
## Stack
Delegated by user: SwiftUI, AppKit, PDFKit, local file system. No cloud dependencies.
## Users
Single local user doing project-based work in Chinese.
## Product Purpose
Find, preview and open files for editing; classify downloaded files into existing project folders.
## Capabilities and Constraints
User confirmed Word, Excel, PDF, images and text. Keep original folders. Offline. No overwrite. No timed polling or startup Downloads scan. Archive sources are read on explicit browsing or refresh. Smart Archive reads document evidence only when invoked; the user chooses a project and confirms before moving files. Arrival/modified/name sorting and navigable archive timeline are required. Project directory chosen in app; no production data supplied.

Parse documents only on explicit naming or archive actions. Search defaults to names/paths. Native immediate selection and guarded preview reloads.

Creation-date month formatting for folders prefers an existing explicit folder month, otherwise its creation month; unavailable creation dates fall back to the operation reference date. Prefix and stem are separated by a space.
Category prefixes use current workspace classification, including manual assignments, with a sanitized name and 其他 fallback even when new-install categories are empty. Normalize explicit repeated month/MMDD/category and legacy content-type prefixes away from the recognized stem without stripping bare numeric titles such as 1001创新. Single and batch smart naming share the formatter; a batch freezes its reference date for initial and alternate candidates. Existing content-extraction priorities remain unchanged. Smart folder execution validates the selected month, calendar-valid MMDD or category prefix in addition to existing identity/version/collision guards.

## Automatically generated category rules
Adding a category requires only its name. Generate and persist local name/synonym/type rules automatically; materialize rules for old custom categories without losing IDs or manual assignments. Unknown or negated names stay conservative. This is vocabulary expansion and literal name analysis, not arbitrary AI semantic understanding; no document-body reads or network are added. Each category has a 规则 editor for keywords, exclusions, extensions, entry scope, priority, enable/disable and regeneration. Preserve built-in procurement precedence with additional exclusions/scope/priority; switch to custom matching only when its positive keywords or extensions are edited; never overwrite user-edited rules on rename. Manual assignments win; prioritize explicit rule priority, meaningful names and specificity over generic types; unresolved ties use the existing fallback. Categorization changes display only.

The approved manual Doubao workflow appears below category creation under the exact red heading 分类设置后，请务必按一下操作。 Step 1, 复制提示词，去豆包官网, directly copies the prompt and opens https://www.doubao.com/ in installed Chrome, otherwise the default browser. Step 2 asks the user to send the prompt and copy Doubao's reply. Step 3, 录入豆包回复, directly reads the clipboard, parses and atomically applies the rules, then shows an inline success/error result. There are no prompt-generation, paste or preview/application modals. The generated prompt includes only existing non-fallback category names, not filenames, paths or document bodies. There is no model API integration, automated website interaction or message sending. Existing local vocabulary generation remains available. The prompt states keyword/extension OR matching and exclusion precedence, avoids generic document extensions for business categories, and requests distinct, conservative terms.

Import accepts a versioned `归屿规则：1` header and six ordered colon-delimited fields per category: 分类, 关键词, 排除词, 扩展名, 范围, 优先级. Require every prompt category; reject missing, duplicate or unknown categories, invalid fields/values and extra prose, while tolerating ASCII colons and a complete plain-text fence. Clicking 录入豆包回复 authorizes direct application of all parsed target rules through the existing atomic writer, replacing their built-in special matching with visible generic rules. Preserve enable states, manual assignments and fallback; leave memory unchanged on write failure. The workflow does not move or rewrite source files. The exclamation entry opens three bundled PNG operation illustrations: copy-prompt, doubao-message and import-rules. These are authored screenshot-like guides, not live captures of the Doubao website. Do not claim validation of actual Doubao replies from synthetic fixtures.

The category workflow has passed local build, self-tests and packaged native-render regression checks; copy feedback appears beside step 1 and import feedback beside step 3. The local dist application is updated without publication, a version increment or installation.
